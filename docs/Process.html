read-all

defn

(Fn [Int] String) 

                        (read-all fd)

reads from the descriptor fd until EOF and returns everything it read as a String.

Returns the empty string for a negative fd. Retries on EINTR; any other read error ends the loop and returns what was read so far. The whole stream is held in memory, so this is not suitable for unbounded output.

run

defn

(Fn [(Ref Command.T a)] Process.Output) 

                        (run cmd)

runs cmd to completion, capturing stdout and stderr separately, and returns an Output.

The two pipes are drained sequentially, stdout first. If the child fills the stderr pipe buffer while this is still reading stdout, both sides block and the call deadlocks. Use run-combined for processes that write a lot to both streams.

On spawn failure the error is returned in Output.stderr with an ExitStatus of code -1 and exited? false.

run-combined

defn

(Fn [(Ref Command.T a)] Process.Output) 

                        (run-combined cmd)

runs cmd to completion with stderr merged into stdout at the OS level, and returns an Output.

Because both streams share one pipe there is only one buffer to drain, so this cannot deadlock the way run can. Output.stderr is always empty. Prefer this for processes with high-volume or interleaved output.

On spawn failure the error is returned in Output.stderr with an ExitStatus of code -1 and exited? false.

spawn

defn

(Fn [(Ref String a), (Ref (Array String) b)] (Result Process.T String)) 

                        (spawn path args)

spawns path with args and returns a handle to the running process, with stdout and stderr on separate pipes and no stdin pipe.

Arguments are passed to execvp(3) directly, not through a shell, so there is no quoting or injection to worry about. args does not include argv[0]; it is prepended from path.

spawn-with-options

defn

(Fn [(Ref String a), (Ref (Array String) b), Bool, Bool] (Result Process.T String)) 

                        (spawn-with-options path args merge-stderr capture-stdin)

spawns path with args, returning a handle to the running process.

When merge-stderr is true the child’s stderr is pointed at the same pipe as its stdout and no separate stderr pipe is opened. When capture-stdin is true a pipe is opened for the child’s stdin, writable through T.stdin.

All parent-side descriptors are set FD_CLOEXEC before the fork, and the child _exits (never exit) so no shared runtime state is flushed twice. On any setup failure every descriptor is closed and a Result.Error is returned.

                        (wait p)
